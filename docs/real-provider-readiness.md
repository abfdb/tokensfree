# 真实供应商接入：上线前门槛

当前版本仍为模拟。以下是后续实现的验收要求，不代表已接入或已授权。

## 账户与费用
- 用户明确允许哪些供应商接收哪类请求；敏感项目可以禁止跨供应商回退。
- 使用各平台官方 API；不提取网页登录 Cookie，不批量注册账号规避额度。
- 核实账号、地域、免费模型白名单和平台侧用完即停保护。未知计费状态直接停止；本地计数不能证明零账单。
- 每个供应商独立确认限速维度与共享额度，不能将 429 一概解释为免费额度耗尽。

## 凭据与网络
- 用户在本机安全输入，使用系统凭据存储；不得写进 Git、浏览器 localStorage、日志或聊天。
- 服务默认仅监听本机；供应商地址固定白名单、TLS 验证开启、限制重定向，不允许请求参数指定任意上游 URL。
- 最小化日志。真实响应缓存可能含敏感内容，需单独制定内存期限、清除机制和持久化策略。

## 请求安全
- 能力先匹配，再排序：文本、视觉、工具调用、上下文、结构化输出不能随意降级。
- 安全拒绝不通过换供应商规避；鉴权错误停用该连接；限流尊重 Retry-After；网络故障必须有限重试。
- 响应已开始流出后，不静默拼接另一供应商结果。
- 有副作用的工具调用不能盲目重放。当前 Idempotency-Key 仅对单进程、5 分钟/100 键内的模拟请求去重；不是持久化 exactly-once 保证，也不能在崩溃后证明上游没有执行。
- 为真实上游设置总截止时间、并发上限、响应大小上限和取消策略。当前全局串行模拟锁不能直接用于慢速真实网络请求，需要每请求键的并发协调。

## 验收顺序
先用本地假上游覆盖 401/403/429/5xx、超时、断流、错误响应和共享配额，再用用户单独授权的测试账户验证。任何真实余额与免费保护结论都必须基于该账户实测，不凭模拟测试宣称完成。
