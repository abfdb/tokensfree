# DSH 流式与工具闭环实验阶段

## 与普通网关的关系

这是独立的 **合成模型实验端点**，不是免费供应商路由。普通 `server.py` 与 UI 不改，原有严格拒绝尚不支持的请求保持不变。真实出口继续关闭。

该拆分是为了用固定官方 DSH 验证 SSE 帧、tool_call 及 tool 结果回传，不把未经验证的供应商、费用条件和工具执行组合进默认服务。通过实验也不能称“已经能用免费模型让 DSH 编程”。

## 安全目标

- 仅 loopback，使用进程随机本地令牌、有限请求大小及读取超时。
- 一次实验只允许一个指定的无副作用读取操作；不发 shell、写文件或联网工具调用。
- 工具调用仅发出一次；收到同一原请求、并发重复或不确定中断时，拒绝再次发出，而不是重新执行可能有副作用的指令。
- tool 结果必须匹配已发出的 call ID 和预期公开 fixture 标记，才产生最终固定回复。
- SSE 开始后禁止自动供应商切换或重放工具调用。若连接断开，实验可失败但不得偷偷再发工具。
- 不读取用户 DSH_HOME、供应商凭据或工作目录；运行固定官方包的实验在无外网命名空间和临时工作目录内进行。

这是 **at-most-once 发出工具指令** 的有限实验，不是持久化 exactly-once 执行。网关无法保证所有客户端不会重复执行；重启会丢失进程内状态。生产化需任务 ID、持久事务状态、用户授权和客户端执行回执。

## 正式支持 DSH 前仍缺什么

需与真实供应商流式响应对应、能力协商、取消和断线恢复、工具授权、响应大小限制、平台错误传播、多轮会话及客户端版本兼容测试。也要先核实中国用户实际供应商资格及零费用条件。GPU 队列、注册辅助、Codex 和 Cursor 是分别的模块与验收项目，本阶段不扩张声明。

## 复现与观察

```sh
python experiments/dsh_tool_roundtrip.py /absolute/path/to/dsh/lib/bin.js
```

需预先准备官方 `@deepseek-ai/dsh@0.2.2-rc.1`，脚本检查包名称/版本元数据；这不替代供应链验证。若 Linux 网络命名空间不可用，停止而不绕过。网络隔离不是文件系统沙箱，临时目录避免正常用户配置加载，但不能对恶意依赖作宿主文件访问保证。

固定版本 DSH 的实际运行已观察到 `tool_call → tool_result → final`，退出码 0，工具为 `read`，派发数 1，公开 fixture 标记与最终文本通过验证。服务器按 SSE 事件分别 flush；不模拟真实模型生成速度，不声称验证了真实上游实时流式延迟。实验脚本不会记录完整系统提示或工具输出，只返回结果摘要。

`agent_fixture.py` 提供 `make_fixture(path)` 工厂；只应传自己创建的公开测试文件，不得传用户敏感路径。它不是对任意工具的执行授权器，也不会实际执行工具；工具由 DSH 执行。

## 验收结果与限制

98 项全套测试通过，包含 9 项实验端点测试。独立审查发现“包含标记的错误结果可能误判成功”，已改为匹配固定版本 DSH 的完整单行 read 输出、call ID 和精确消息字段集合，并加入错误/附加文字回归测试。修复后真实 DSH 再次退出 0，工具调用与结果事件各一次。

断线测试通过丢弃已生成 SSE 响应验证“不重发”状态机，不代表完整 TCP 断线/客户端崩溃恢复已覆盖；此时会话可能停在等待状态，只能放弃该实验，不能自动补发。固定公开标记不提供防伪证明，完整格式匹配是 fixture 验证，不是通用工具结果可信度判断。仅适配这次固定 DSH read 格式，客户端版本更新可能需要重新验收。
